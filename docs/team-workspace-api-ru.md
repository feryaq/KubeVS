# Серверный API совместной работы KubeVS

Эта версия Connector содержит безопасную серверную основу для
удалённого редактирования в VS Code. API доступен только после авторизации админским
или личным токеном и работает исключительно внутри серверной папки `kubejs`.

## Возможности

В `hello.capabilities` сервер сообщает:

```json
{
  "workspaceFiles": true,
  "workspaceLocks": true,
  "workspaceMaxFileBytes": 1048576
}
```

Каждое соединение получает случайный `hello.session.sessionId`. Блокировка
принадлежит одновременно пользователю и конкретному соединению. При закрытии
WebSocket все его блокировки освобождаются.

`hello.session.permissionLevel` содержит уровень прав Minecraft, с которым был
выдан личный токен. Возможности разделены по принципу минимальных привилегий:

| Уровень     | Доступ                                                              |
| ----------- | ------------------------------------------------------------------- |
| `0`         | подключение, registries и recipes без чтения серверных файлов       |
| `1`         | список и чтение файлов `kubejs`                                     |
| `2+`        | чтение, блокировки, запись, журналы и разрешённый владельцем reload |
| админ-токен | уровень `4`                                                         |

Булевы поля `workspaceFiles`, `workspaceLocks`, `logs` и `reload` в capabilities
уже учитывают права текущей сессии. Сервер всё равно повторно проверяет уровень
на каждом запросе: подмена capabilities на стороне клиента ничего не даёт.

Поддерживаются запросы:

- `workspace.files.list` — список файлов, размеров и SHA-256-ревизий;
- `workspace.files.read` — содержимое и текущая ревизия файла;
- `workspace.files.write` — атомарная запись;
- `workspace.locks.acquire` — захват файла;
- `workspace.locks.release` — освобождение своего файла;
- `workspace.locks.status` — состояние одного файла;
- `workspace.locks.list` — все активные блокировки.

## Безопасная запись

Перед записью клиент обязан захватить путь:

```json
{
  "type": "request",
  "requestId": "1",
  "method": "workspace.locks.acquire",
  "params": { "path": "server_scripts/main.js" }
}
```

Если `acquired` равен `false`, ответ содержит имя и идентификатор сессии
текущего владельца. Перезаписывать такой файл нельзя.

После чтения клиент передаёт полученную ревизию:

```json
{
  "type": "request",
  "requestId": "2",
  "method": "workspace.files.write",
  "params": {
    "path": "server_scripts/main.js",
    "content": "ServerEvents.recipes(event => {})\n",
    "expectedRevision": "sha256-ревизия-из-read"
  }
}
```

Для нового файла используется пустая ревизия `""`. При несовпадении сервер
возвращает `REVISION_CONFLICT` и `actualRevision`, не изменяя файл. Если
блокировка не принадлежит соединению, возвращается `LOCK_REQUIRED`.

## Ограничения безопасности

- абсолютные пути и выход через `..` запрещены;
- символические ссылки не читаются и не используются для записи;
- размер одного файла ограничен 1 МиБ;
- список ограничен 2000 файлами и бюджетом хеширования 64 МиБ;
- временный файл создаётся в целевой папке, затем заменяется атомарным move;
- содержимое или токены не попадают в журнал, записываются только имя автора и путь.

Расширение подключает API как `kubevs-remote` FileSystemProvider. В разделе
**Подключение** выберите **Открыть серверный файл**. Перед открытием KubeVS захватывает блокировку;
если файл занят, показывается ник участника. Обычное сохранение VS Code отправляет ожидаемую
SHA-256-ревизию, поэтому устаревшая копия не перезапишет новую. При закрытии вкладки блокировка
освобождается; список занятых файлов доступен рядом в Connection View.

Текущая вертикаль редактирует существующие файлы. Создание папок, переименование и удаление через
remote-provider пока намеренно отключены.
