# Командная работа и авторизация KubeVS

KubeVS Connector 1.1.2 использует персональные аккаунты и именованные роли. Каждый токен привязан
к UUID Minecraft. На сервере хранится только SHA-256 digest токена; исходный секрет показывается
один раз.

## Быстрое подключение

1. Игрок заходит на сервер и выполняет:

   ```text
   /kvs join
   ```

2. Нажимает **Копировать код подключения**.
3. В VS Code открывает палитру команд и выбирает **KubeVS: Подключиться по коду /kvs join**.
4. Вставляет строку вида `kubevs://server:32145?token=...`.
5. KubeVS сохраняет токен в SecretStorage и автоматически добавляет серверную папку
   **KubeJS — <игрок>** в Explorer.

Повторный `/kvs join` немедленно отзывает предыдущий токен и закрывает старую сессию. Назначенная
администратором роль сохраняется.

## Роли

| Роль       | Возможности                                                                   |
| ---------- | ----------------------------------------------------------------------------- |
| `viewer`   | Реестры, рецепты, просмотр серверной папки KubeJS                             |
| `editor`   | Всё выше, создание, сохранение, copy, rename и delete файлов/папок            |
| `operator` | Всё выше, чтение логов и Save and Reload, если reload разрешён в конфигурации |
| `admin`    | Полные возможности Connector                                                  |

Сервер проверяет permission при каждом запросе. Поля capabilities в VS Code используются только
для интерфейса и не являются границей безопасности.

## Управление аккаунтами

Команды требуют Minecraft permission level 4:

```text
/kvs users
/kvs role <игрок> <viewer|editor|operator|admin>
/kvs revoke <игрок>
```

Смена роли и отзыв доступа закрывают активные соединения игрока. После смены роли используется тот
же токен; после revoke игрок должен снова выполнить `/kvs join`.

Админ-доступ сервера:

```text
/kvs auth
/kvs auth copy
/kvs auth rotate
```

Ротация админ-токена требует подтверждения и отключает все сессии, использующие старый секрет.
Консоль сервера никогда не печатает токен.

## Настройки выдачи аккаунтов

`config/kubevs-connector.toml`:

```toml
[permissions]
joinPermissionLevel = 2
defaultRole = "EDITOR"
allowReload = false
```

- `joinPermissionLevel` определяет, кто может создать аккаунт через `/kvs join`;
- `defaultRole` применяется только при первом создании аккаунта;
- следующая выдача токена сохраняет роль, назначенную через `/kvs role`.

Файл `config/kubevs-player-tokens.tsv` содержит UUID, имя, роль и digest токена. Его можно
резервировать, но нельзя публиковать: метаданные участников всё равно являются приватными.

## Конфликты редактирования

При открытии файла VS Code захватывает серверную блокировку. В Connection View видно, кто работает
с занятыми файлами. Второй пользователь может читать файл, но сохранение будет запрещено с именем
владельца.

Каждая запись также передаёт SHA-256-ревизию. Даже после внешнего изменения через SSH или панель
устаревшая вкладка не перезапишет серверный файл. KubeVS оставит локальные изменения
несохранёнными и предложит сравнить их с новой версией.

## Dedicated server

Сам Connector не реализует TLS. Для публичной сети используйте VPN или TLS reverse proxy. Пример
публичного WSS endpoint:

```toml
[network]
host = "127.0.0.1"
port = 32145
allowRemote = false
publicHost = "kubevs.example.com"
publicPort = 443
publicSecure = true
```

Reverse proxy принимает `wss://kubevs.example.com:443` и передаёт WebSocket на
`127.0.0.1:32145`. `/kvs join` автоматически создаст правильный WSS-код.

Для VPN можно привязать Connector к VPN-интерфейсу, включить `allowRemote = true` и оставить
`publicSecure = false`. Не открывайте обычный `ws://` в публичный интернет.
