# Проверка KubeVS 1.7.0

## Живой MCP

Проверка выполнена через подключённый KubeVS MCP в пользовательской игре Minecraft 1.21.1. Установлены Connector 1.6.0, KubeJS 2101.7.2-build.377, GTCEu 8.0.0-SNAPSHOT+36a6b38, Create 6.0.10. Доступ — личная сессия администратора. MCP прочитал список модов, реестры, рецепты, файлы и состояние сервера.

В отдельной папке `server_scripts/kubevs/mcp_demo/` созданы два файла без изменения существующих скриптов:

- `packed_mud.js`: грязь + пшеница → саманная глина, исходные затраты ванильного рецепта.
- `gravel_to_flint.js`: гравий → каменная пыль + 33% кремня, 400 тиков, 2 EU/t; копия исходного рецепта дробилки GTCEu.

Предварительная генерация, сохранение, обратное чтение файлов и проверка проекта через MCP прошли. После выполненного пользователем `/reload` оба рецепта найдены и прочитаны из живого реестра. JSON машинного рецепта полностью совпал с оригиналом, включая входы, выходы, шанс, время и питание. GTCEu добавил тип машины к ID: фактический ID — `kubevs:macerator/mcp_demo/gravel_to_flint`; ванильный — `kubevs:mcp_demo/packed_mud`. MCP теперь возвращает `effectiveRecipeId` для сгенерированного машинного рецепта.

В текущей пользовательской игре `permissions.allowReload=false`, поэтому ресурсную перезагрузку сделал пользователь. Установленный мод не заменялся и Minecraft не перезапускался. Новый MCP-инструмент управления reload требует обновления обоих компонентов до 1.7.0 и перезапуска Minecraft/сервера для загрузки нового JAR. Горячая подмена классов игры не использовалась.

## Локальные проверки

- Locked install и production audit прошли, известных уязвимостей не найдено.
- `pnpm check:release`: метаданные, ESLint, TypeScript, тесты, сборка и Prettier.
- 7 parser + 4 protocol + 12 recipe-model + 75 extension + 3 MCP transport теста; 27 интеграционных тестов в Code OSS на отдельном Xvfb-дисплее.
- Интеграционный MCP-тест проверяет отказ редактору, включение reload администратором, вызов reload, отключение и последующий отказ. Смена настройки обновляет уже существующий hello/capability-объект.
- Упакованный minified VSIX отдельно прошёл те же 27 интеграционных тестов на виртуальном дисплее.
- Connector: 26 тестов без ошибок; отдельно проверены отказ всем неадминистраторам, сохранение настройки и отсутствие применения при ошибке записи, русский fallback и русские метаданные в сгенерированном TOML.
- Из production JAR извлечены и проверены русское название/описание, автор feryaq и версия 1.7.0. Исправлена кодировка Gradle properties, которая иначе портила кириллицу.
- Headless Chromium: 66 базовых рендеров, 64/64 проверки, без ошибок и горизонтального переполнения. Новые шаги проверяют список/произвольный тип машины, уровни/произвольное EU/t, секунды → тики, скрытые дополнительные поля, шансы и добавление жидкости.

## Визуальная приёмка

Осмотрены реальные HTML редактора: простой GTCEu при 390 px в тёмной теме и расширенная форма при 1440 px. Также автоматическая матрица покрывает 320/390/800/1440 px, светлую и тёмную темы. Основной экран GTCEu содержит машину, время, питание, вход и выход; дополнительные возможности сохранены под раскрытием. Рендеры находятся локально в `artifacts/home-1.7.0/screenshots`.

Запуск Code выполнялся на частном виртуальном дисплее, Chromium — headless. Фокус пользовательской игры не менялся. Внешний вид русского меню NeoForge в пользовательской игре не проверялся: новый мод ещё не загружен. Новый Connector reload-путь проверен тестами и сборкой, но не в живом пользовательском процессе. Фактическое выполнение рецепта машиной/верстаком не проверено: установлена его успешная регистрация и корректная сериализация.
