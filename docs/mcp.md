# MCP-сервер KubeVS

KubeVS включает локальный HTTP MCP-сервер на официальном SDK. Это функция расширения VS Code: отдельное приложение, пакет или фоновый демон не нужны. Сервер работает внутри extension host, использует открытый проект и ту же активную сессию Connector, что и интерфейс KubeVS. MCP не возвращает сохранённые токены Connector. Инструмент подключения принимает приватный код `/kvs join`, только если клиент явно передаст его.

## Запуск

MCP доступен только в доверенной рабочей области VS Code. По умолчанию сервер выключен (`kubevs.mcp.enabled: false`). Запустите его командой **KubeVS: Start MCP Server**. Карточка **MCP server** на главной вкладке открывает меню управления в native Quick Pick. Команда **KubeVS: Copy MCP Configuration** копирует конфигурацию для клиента.

По умолчанию сервер слушает `127.0.0.1:32146/mcp`. Настройка `kubevs.mcp.port` задаёт порт; значение `0` выбирает свободный порт автоматически. При автоматическом выборе скопируйте конфигурацию после запуска сервера, чтобы использовать его актуальный адрес. Сгенерированный ключ доступа хранится в VS Code SecretStorage.

## Подключение клиента

Для клиента, который принимает конфигурацию в формате `mcpServers`, запись имеет такой вид:

```json
{
  "mcpServers": {
    "kubevs": {
      "type": "http",
      "url": "http://127.0.0.1:32146/mcp",
      "headers": {
        "Authorization": "Bearer <ключ>"
      }
    }
  }
}
```

Используйте полный блок, скопированный командой KubeVS, если порт выбран автоматически. Путь `/mcp` и заголовок Bearer обязательны. Не публикуйте ключ и не передавайте его посторонним. Формат `mcpServers` выше — пример для клиентов, использующих такой JSON; способ добавления HTTP MCP-сервера и расположение конфигурации зависят от клиента. KubeVS не изменяет настройки ИИ-клиента автоматически.

## Инструменты

MCP использует функции расширения и Connector в рамках текущего проекта и текущей сессии:

- Состояние KubeVS и подключения.
- Чтение, создание, изменение и удаление локальных или удалённых файлов KubeJS; операции записи защищены проверкой ревизии.
- Генерация рецептов в JSON, включая Create mechanical crafting и GTCEu Modern 1.21.1; генерация LootJS, стартовых предметов и блоков, пользовательских схем.
- Просмотр, удаление, восстановление и замена рецептов.
- Поиск по реестрам, тегам и модам; чтение журналов Connector, блокировок и предмета в руке.
- Построение Craft Graph, диагностика и запрос перезагрузки скриптов при наличии разрешений Connector.

Генераторы по умолчанию возвращают предварительный просмотр и не записывают файл (`save: false`). Чтобы создать файл, явно передайте `save: true`. Перед перезаписью получите текущую ревизию через `read_file` и укажите её как `expectedRevision`. Файлы ограничены UTF-8 и размером 512 КиБ.

Код регистрации, выполняемый при запуске Minecraft, требует перезапуска игры или сервера. Перезагрузка рецептов и LootJS — отдельное явное действие, доступное только если Connector разрешает его для этой сессии.

## Границы доступа

Сервер принимает соединения только на loopback (`127.0.0.1`) и требует Bearer-ключ. Запросы с browser origin отклоняются. Доступ к файлам ограничен доверенной рабочей областью и разрешёнными файлами KubeJS; произвольные пути, shell, команды операционной системы и запуск произвольного кода недоступны. Для удалённых файлов действуют права и блокировки активной сессии Connector.

При подключении VS Code через SSH расширение и MCP-сервер работают на удалённой машине, где запущен extension host. Адрес `127.0.0.1` относится к этой машине. Клиент, работающий на другом компьютере, не сможет обратиться к нему напрямую: настройте SSH-туннель или другой защищённый сетевой путь и укажите клиенту достижимый адрес сервера.

## GregTech CEu Modern 1.21.1

Инструмент `kubevs_generate_gregtech_recipe` использует KubeJS builder GTCEu, а не универсальный JSON. Тип машины задаётся полем `machine` (например, `assembler`); убедитесь, что он зарегистрирован в подключённой сборке. Поддерживаются item/fluid IO, вероятностные предметные выходы, повторно используемые предметы/жидкости, `circuit`, `duration` в тиках, знаковый `eut` в EU/t и необязательный `posY`. Шанс предметного выхода — число от 0 до 1 с точностью GTCEu 1/10000. Количество жидкости — mB. Отрицательный EU/t обозначает генерацию; пересчёт разгона и напряжения автоматически не выполняется. Для обнаружения интеграции нужен Connector 1.5.0.

Редактор Mod recipe → GregTech использует тот же генератор. Ветка API проверена по [GTRecipeSchema 1.21](https://github.com/GregTechCEu/GregTech-Modern/blob/1.21/src/main/java/com/gregtechceu/gtceu/integration/kjs/recipe/GTRecipeSchema.java). Пользовательские машины, research/cleanroom и произвольные дополнительные условия задавайте по документации вашей версии; этот генератор их не создаёт.
